Nota: la historia #2 (crear compra) no se dividió en sub-historias (selector de proveedor / líneas / totales / forma de pago) porque ninguna de esas partes entrega valor de forma aislada — es un único formulario indivisible, igual criterio que POS/Cotizaciones. Todas las historias trazan a `## What Changes`.

## Why

El backend de Compras (change `add-purchases-crud`) expone la capacidad de registrar compras a proveedores, cancelarlas y gestionar cuentas por pagar vía abonos, pero sin interfaz no es utilizable por el equipo operativo. Se necesita la misma cobertura de UI que ya existe para Ventas/Cotizaciones/Devoluciones/Abonos: listado, detalle, formulario de creación y las acciones de ciclo de vida (cancelar compra, registrar/cancelar abono a proveedor), además de la entrada correspondiente en la navegación para que el módulo sea descubrible.

## What Changes

- Nueva página `/purchases` — listado paginado con filtros proveedor/sucursal/estado/fechas, búsqueda server-side de proveedor (historia #1).
- Nueva página `/purchases/new` — formulario de creación con `ProviderPicker` (+ quick-add), líneas de producto editables y cálculo de totales en cliente (historia #2).
- Nueva página `/purchases/[id]` — detalle con líneas, metadatos, sección de abonos a proveedor y acciones contextuales (historia #3).
- Nuevos modales: `RegisterProviderPaymentModal` (historia #4), `CancelProviderPaymentModal` (historia #5), `CancelPurchaseModal` (historia #6).
- Nuevo `ProviderPicker` (`app/(private)/purchases/_blocks/`) y `ProviderQuickAddModal`, reutilizando `createProvider` service ya existente en `catalogs/providers`.
- Nuevo `computePurchaseTotalsClient` (`app/(private)/purchases/_logic/lib/`) — puerto puro cliente-side, mismo patrón que `computeReturnTotalsClient`/`computeTotalsClient` de POS.
- Nuevo item `purchases` en `app/_components/organisms/NavigationRail/items.ts` (historia #7).
- Toda la capa `_logic/` (`hooks/`, `services/`, `schemas/`, `types/`, `errors.ts`) del feature `purchases`, consumiendo los endpoints de `add-purchases-crud` vía `authFetch`.

## Capabilities

### New Capabilities
- `purchases-ui`: interfaz de usuario del módulo de Compras — listado, creación, detalle y acciones de ciclo de vida (cancelar compra, registrar/cancelar abono a proveedor).

### Modified Capabilities
- `panel-shell`: el requirement "Navigation rail item catalogue" (catálogo ordenado de items del `NavigationRail`) se modifica para incluir el nuevo item `purchases`.

## Impact

- **Archivos de código nuevos**: `app/(private)/purchases/**` (page.tsx de listado/detalle/creación, `_blocks/`, `_logic/{hooks,services,schemas,types}/`, `errors.ts`).
- **Archivos modificados**: `app/_components/organisms/NavigationRail/items.ts` (nuevo item), potencialmente `app/(private)/catalogs/providers/_logic/services/createProvider.ts` (reexportado/reutilizado, no modificado).
- **Depende de**: change `add-purchases-crud` (backend) ya propuesto — los endpoints `/api/v1/admin/purchases`, `/api/v1/admin/purchases/:id/provider-payments`, `/api/v1/admin/provider-payments/:id/cancel` deben existir antes de implementar este change.
- **Sin cambios de API, BD ni RBAC** — este change es 100% frontend presentational, consumiendo permisos ya seminados por el change backend (`purchases:read/create/cancel/pay/pay_cancel`).
- **Tests**: unit tests de UI bajo `tests/unit/ui/(private)/purchases/` para bloques y hooks, siguiendo el patrón de `tests/unit/ui/.../returns/`.
