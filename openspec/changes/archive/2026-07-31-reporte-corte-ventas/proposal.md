> Notas: feature dividida en 5 historias (backend corte S1, neto de caja S2, PDF S3, UI S4, corte de caja/cobranza detallada S5). S2 se separa de S1 por ser un concepto de dominio distinto (caja vs ventas) y testeable aparte. S5 es una capability nueva y hermana (`cash-cut-api`) sobre datos de `customer_payments` join `sales`/`customers`/`payment_methods` — grano de fila (un abono por fila), no una extensión de los agregados de S1. Nuevo permiso RBAC `reports:sales_cut_read` (admin+operator+viewer, como `reports:account_statements_read`) y nuevo permiso `reports:cash_cut_read` (mismos 3 roles). `/reports` pasa de redirect a hub con tarjetas (Estados de Cuenta, Corte de Ventas, Corte de Caja).

## Why

El panel registra cada venta (`sales`) con `subtotal`, `taxTotal`, `total`, `status`, `paymentMethodId`, `cashierId`, `branchId`, `createdAt`, pero **no hay ninguna vista que cierre el día**: el cajero no puede saber cuánto se vendió, con cuántos tickets, cómo se repartió entre efectivo y crédito, ni cuánto entró realmente a caja (sumando abonos cobrados y restando devoluciones). Hoy eso se calcularía a mano o consultando la BD.

Los datos ya existen dispersos entre `sales`, `customer_payments` (abonos) y `returns` (devoluciones). El módulo `reports` ya fija el patrón —use case + port + repos Prisma/InMemory, guard RBAC `reports:*`, branch scoping, salida JSON + PDF con `@react-pdf/renderer`, tal como el recién agregado Estado de Cuenta— así que el Corte de Ventas es un nuevo tipo de reporte que reutiliza esa infraestructura.

## What Changes

- **Backend — permiso RBAC**: nuevo `reports:sales_cut_read` en `prisma/seed.ts`; otorgado a `admin`, `operator`, `viewer` (paralelo a `reports:account_statements_read`). Idempotente.
- **Backend — módulo `reports`**: nuevo port `SalesCutRepository` con consultas agregadas sobre `sales` (por método de pago, día, cajero, sucursal; y ventas canceladas aparte), `customer_payments` (abonos completed) y `returns` (devoluciones completed). Impl `PrismaSalesCutRepository` (`groupBy`/agregados) e `InMemorySalesCutRepository` (tests).
- **Backend — servicio de dominio puro** `SalesCutAssembler`: ensambla el DTO a partir de los agregados crudos, calcula `netCash = grossSales + paymentsReceived − returnsRefunded` y ordena los desgloses. Banker's rounding a 4 decimales, consistente con los calculadores existentes.
- **Backend — use case** `GetSalesCutReportUseCase`: aplica filtros (sucursal/cajero/método/rango, preset "hoy" resuelto en el controller) y arma el DTO listo para JSON o PDF.
- **Backend — endpoint** en `ReportsController` + ruta `GET /api/v1/admin/reports/sales-cut`, con `?format=json|pdf`, branch scoping y guard `reports:sales_cut_read`.
- **Backend — PDF**: `SalesCutReportPdf.tsx` (encabezado + totales + neto de caja + tablas de desglose) vía `renderToBuffer`.
- **Frontend — hub `/reports`**: `page.tsx` deja de redirigir y pasa a ser un hub con tarjetas ("Estados de Cuenta", "Corte de Ventas").
- **Frontend — vista `/reports/sales-cut`**: toggle "Hoy | Rango", filtros, tarjetas de totales + neto de caja, tablas de desglose, botón Exportar PDF. `_logic/{services,hooks,types}` + `_blocks` presentacionales.
- **Backend — permiso RBAC (S5)**: nuevo `reports:cash_cut_read` en `prisma/seed.ts`; otorgado a `admin`, `operator`, `viewer`. Idempotente.
- **Backend — módulo `reports` (S5)**: nuevo port `CashCutRepository` con consulta de filas de `customer_payments` (`status='completed'`) unidas a `sales`/`customers`/`payment_methods` en el periodo. Impl `PrismaCashCutRepository` e `InMemoryCashCutRepository` (tests).
- **Backend — servicio de dominio puro (S5)** `CashCutAssembler`: por fila calcula `days` (F.Cobro − Fec-Fact) e `ivaAmount`/`taxRatePct` prorrateados desde la venta ligada; arma `totals` (total cobrado, total IVA) y `byPaymentMethod` (desglose dinámico por catálogo real). Banker's rounding a 4 decimales, consistente con `SalesCutAssembler`.
- **Backend — use case (S5)** `GetCashCutReportUseCase`: aplica filtros (sucursal/cliente/método/rango obligatorio) y arma el DTO listo para JSON, PDF o Excel.
- **Backend — endpoint (S5)** en `ReportsController` + ruta `GET /api/v1/admin/reports/cash-cut`, con `?format=json|pdf|xlsx`, branch scoping y guard `reports:cash_cut_read`.
- **Backend — PDF y Excel (S5)**: `CashCutReportPdf.tsx` (encabezado + tabla de filas + totales + desglose) vía `renderToBuffer`; `buildCashCutWorkbook.ts` (mismo patrón que `buildKardexWorkbook.ts`, dependencia `xlsx` ya instalada) para `.xlsx`.
- **Frontend — hub `/reports` (S5)**: tercera tarjeta "Corte de Caja (Cobranza)" → `/reports/cash-cut`.
- **Frontend — vista `/reports/cash-cut` (S5)**: filtros sucursal+rango, tabla de filas (12 columnas), tarjetas de totales, tabla de desglose por forma de pago, botones Exportar PDF/Excel. `_logic/{services,hooks,types}` + `_blocks` presentacionales.

## Capabilities

### New Capabilities
- `sales-cut-api` — endpoint, DTO, reglas de agregación, canceladas aparte y neto de caja del corte de ventas (backend).
- `cash-cut-api` — endpoint, DTO, filas de cobranza (abonos), prorrateo de IVA, desglose dinámico por forma de pago y export PDF/Excel del corte de caja (backend). (S5)

### Modified Capabilities
- `reports-api`: se documenta el nuevo tipo de reporte (sales cut) alojado en el mismo módulo/controller.
- `reports-ui`: `/reports` pasa a hub; nueva sub-vista `/reports/sales-cut` con toggle, desgloses y export; nueva sub-vista `/reports/cash-cut` con filas de cobranza y export PDF/Excel (S5).
- `rbac`: nuevo permiso `reports:sales_cut_read` y su reparto por rol; nuevo permiso `reports:cash_cut_read` y su reparto por rol (S5).

## Impact

- **Sin migración de base de datos.** Todo se deriva de tablas existentes (`sales`, `customer_payments`, `returns`, `payment_methods`, `users`, `branches`, `customers`).
- Requiere re-ejecutar `npm run seed` para registrar los permisos (idempotente).
- Solo lectura: no muta ventas, abonos, devoluciones ni inventario.
- Archivos backend nuevos: 1 port, 2 repos, 1 servicio de dominio, 1 use case, DTOs, 1 PDF, entradas en controller/DI, 1 ruta.
- Archivos frontend nuevos: hub `/reports` (editar `page.tsx`) + módulo `/reports/sales-cut` (page, `_blocks`, `_logic`).
- Tests: use case con `InMemorySalesCutRepository`; test del `SalesCutAssembler` (neto de caja, canceladas aparte, desgloses); tests de controller (RBAC, scoping, format, from>to).
- **S5 (cash-cut) — archivos backend nuevos**: 1 port, 2 repos, 1 servicio de dominio, 1 use case, DTOs, 1 PDF, 1 builder xlsx, entradas en controller/DI, 1 ruta. Segundo consumidor de la dependencia `xlsx` ya instalada (el primero es Kardex de inventario).
- **S5 (cash-cut) — archivos frontend nuevos**: 3ra tarjeta en el hub (editar `ReportsHubPage.tsx`) + módulo `/reports/cash-cut` (page, `_blocks`, `_logic`).
- **S5 (cash-cut) — tests**: use case con `InMemoryCashCutRepository`; test del `CashCutAssembler` (prorrateo de IVA, `days`, desglose dinámico); tests de controller (RBAC, scoping, format json/pdf/xlsx, from>to).
