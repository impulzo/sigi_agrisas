Decisiones de ambigüedad iniciales (auto-crear producto nuevo, sin precio base global cuando no existe en Matriz, upsert que pisa `quantity`, crear fila con `quantity=0`) fueron confirmadas explícitamente por el usuario antes de la primera versión de esta tabla; las historias 5 y 6 se agregaron después, a pedido explícito del usuario durante `apply`, con decisiones de normalización/matching tomadas por el asistente (documentadas arriba) sin ronda adicional de preguntas — el usuario indicó continuar sin más confirmaciones intermedias en esta sesión.

## Why

El seeder v2 actual (`prisma/seeds/inventory.ts` + `data/inventario-agrisas-v2.ts`) sólo carga el catálogo e inventario inicial de la sucursal Matriz, y quedó desactualizado frente a `INVENTARIOS TIENDAS.xlsx`, que trae datos más recientes también para Matriz (hoja `INV AGRISAS`). Las 5 tiendas reales (Chichicapam, Zarioz, Huajuapan, Pradera, Tlaxiaco) tienen su propio inventario físico y, para varios productos, un precio de venta distinto al de Matriz — patrón ya detectado y documentado en `add-branch-scoped-prices` (ej. `KER KAB 1L` a $3,666.65 en Matriz vs $699.35 en 4 tiendas vs $770.00 en Tlaxiaco), change que ya implementó el soporte de `ProductPrice.branchId` y está en 44/44 tareas, verify limpio, pendiente sólo de archivar. Con el modelo de datos ya listo, falta el paso de carga completo: leer las 6 hojas del Excel real, refrescar Matriz con los datos vigentes, y reconciliar Tlaxiaco (que usa una numeración de code interna incompatible) contra el mismo catálogo compartido que usan las demás tiendas.

## What Changes

- Nuevo generador offline `prisma/seeds/data/generate-inventario-tiendas-data.ts`: lee las 6 hojas de `INVENTARIOS TIENDAS.xlsx`, cada una con su propio mapeo de columnas; emite `prisma/seeds/data/inventario-tiendas-v3.ts` con filas normalizadas por hoja (forma extendida para Agrisas — multi-tier — y Tlaxiaco — code numérico crudo + departamento explícito).
- Nuevo seeder runtime `prisma/seeds/inventory-tiendas.ts` (`npm run seed:inventory-tiendas`), que NO lee el xlsx — sólo el archivo TS embebido.
- El seeder runtime: refresca Matriz (producto + precio base multi-tier + inventario) desde `INV AGRISAS`; hace upsert de las 5 sucursales de tienda faltantes; empareja Chichicapam/Zarioz/Huajuapan/Pradera por `code` exacto; empareja Tlaxiaco por nombre normalizado (code sintetizado si no hay match); hace upsert de inventario multi-sucursal; crea `ProductPrice` branch-scoped sólo cuando el precio diverge del base.
- Aislamiento por-producto sin transacción global; reporte estructurado final con conteos y errores, incluyendo matches/no-matches de Tlaxiaco.
- **No modifica** `inventory.ts`/`inventario-agrisas-v2.ts` como archivos (siguen existiendo, v2 sigue siendo runnable de forma independiente) — este seeder es adicional y, al correr después, refresca los mismos productos de Matriz con datos más nuevos vía su propio flujo, no editando el código de v2.

## Impact

- **Nuevos archivos**: `prisma/seeds/data/generate-inventario-tiendas-data.ts`, `prisma/seeds/data/inventario-tiendas-v3.ts` (generado), `prisma/seeds/inventory-tiendas.ts`, `prisma/seeds/lib/normalizeProductName.ts` (normalización de nombre para matching de Tlaxiaco).
- **`package.json`**: nuevo script `seed:inventory-tiendas`.
- **DB**: refresh de filas existentes en `products`/`product_prices`/`branch_inventory` para Matriz (vía `INV AGRISAS`); nuevas filas en `branches` (5 tiendas), `products` (productos nuevos vía tiendas o Tlaxiaco sin match), `branch_inventory` (Matriz + 5 tiendas), `product_prices` (overrides branch-scoped) — ninguna migración de schema (ya migrado por `add-branch-scoped-prices`).
- **Dependencia dura**: requiere que `add-branch-scoped-prices` esté implementado en la rama de trabajo (ya lo está — 44/44 tareas, pendiente sólo de `opsx:archive` explícito).
- **No afecta** UI, API HTTP, ni módulos POS/Cotizaciones/Reportes directamente — es un script de un solo uso (dev/ops), consistente con el resto de `prisma/seeds/`.
