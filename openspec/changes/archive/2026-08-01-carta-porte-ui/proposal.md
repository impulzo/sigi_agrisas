El punto 4 original (manejo de errores) se conservó como historia propia porque tiene sus propios criterios de aceptación verificables por cada código de error, distintos del happy path de creación (Historia 3)._

## Why

El backend de traspasos (`src/modules/waybills/`, capability `waybills-api`, change `add-carta-porte`) especifica creación con timbrado atómico, cancelación, listado y descarga bajo `/api/v1/admin/waybills`, con permisos `waybills:read`/`waybills:write`/`waybills:cancel` ya definidos. Sin interfaz, el negocio no puede registrar ni consultar traspasos entre sucursales desde el panel — la única vía sería llamar la API directamente. Esta propuesta cubre exclusivamente el front end, siguiendo la arquitectura `Atomic Design + Route Groups + _logic/` del proyecto, replicando el patrón de `billing-ui` (que depende de `add-billing-facturama` de la misma manera).

## What Changes

- **Nueva sección `/waybills`** (NavigationRail, gated por `waybills:read`, icon `local_shipping`): listado paginado con filtros (sucursal con bypass, estado, rango de fechas) y branch scoping por origen O destino, igual que el backend.
- **`/waybills/[id]`**: detalle con ubicaciones snapshoteadas, mercancías, vehículo/operador, estado del CFDI, descarga PDF/XML, cancelación (`waybills:cancel`) con motivo.
- **`/waybills/new`** (gated `waybills:write`): selector origen/destino (excluye duplicados en UI), líneas de mercancía desde el catálogo de productos (reusa `ProductCatalogPanel`/`ProductCatalogTable` del POS), formulario libre de vehículo y operador (sin catálogo maestro — no existe), fecha/hora salida-llegada, distancia. Envío = timbrado inmediato, redirige al detalle.
- **Manejo de errores tipados**: `InvalidBranchPairError`, `BranchAddressIncompleteError(missingFields)` (con enlace a `/catalogs/branches`), `InsufficientStockAtOriginError(productId)` (resalta línea), `FacturamaStampError(detail)`, `WaybillAlreadyCancelledError`.
- **Servicios tipados + hooks** bajo `app/(private)/waybills/_logic/`: encapsulan `authFetch`, normalizan errores HTTP del backend, aceptan `fetchImpl?` para tests.
- **Reuso**: `ProductCatalogPanel`/`ProductCatalogTable` del POS, `CatalogToolbar`/`CatalogPagination`/`EmptyState`/`ConfirmDialog` compartidos, `useHeadquarters`-style hook adaptado para selector de sucursales (o reuso directo de `Branch` options ya existentes en `providers`/`branches`).
