El punto 7 (RBAC) se refleja como Criterios de Seguridad transversales en cada historia, no como historia propia._

## Why

Hoy el sistema permite que `branch_inventory.quantity` quede negativo tras una venta o cancelación de devolución, documentando explícitamente en `openspec/specs/inventory-api/spec.md:139` que esa deuda "debe saldarse con una futura transferencia entre sucursales (**módulo `branch_transfers`, reservado para un cambio posterior**)". Ese módulo nunca se construyó. En paralelo, el folio `TS` (`Traspaso entre inventarios`, `scope: INVENTORY`) ya está sembrado en `prisma/seeds/folios.ts:30` pero ningún módulo lo consume.

Además, el SAT exige el **Complemento Carta Porte** para cualquier transporte terrestre de mercancías dentro de México — incluyendo movimientos internos de mercancía propia entre sucursales, sin venta de por medio (CFDI tipo `Traslado`). Sin este módulo, cualquier traspaso físico de inventario entre sucursales que use la vía pública queda sin soporte fiscal, exponiendo al negocio a sanciones del SAT.

Este cambio implementa el módulo `waybills` (Carta Porte) como la materialización del `branch_transfers` reservado, extendido con los datos SAT del complemento (ubicaciones, mercancías, autotransporte, figura de transporte — capturados libres, sin catálogo maestro, decisión explícita del negocio para mantener el alcance v1 acotado). Alcance nacional únicamente; no cubre comercio exterior ni CFDI de Ingreso con Carta Porte (eso queda fuera — ver Non-Goals en `design.md`).

## What Changes

- **Nuevo módulo hexagonal `src/modules/waybills/`** (capability `waybills-api`): dominio puro (`Waybill`, `WaybillItem`, value-objects, errores), application (ports `WaybillRepository` + `WaybillFacturamaGateway`, use cases, DTOs, mappers), infraestructura (`PrismaWaybillRepository`, `FacturamaRestGateway`/`FakeFacturamaGateway` propios del módulo, controller, DI).
- **Migración Prisma** `add_waybills_tables_and_branch_address`:
  - `waybills`: folio `TS` (`folioId`/`folioNumber`), `originBranchId`/`destinationBranchId`, `status` (`completed`/`cancelled`), vehículo libre (`vehiclePlate`, `vehicleConfig`, `vehiclePermitType`, `vehiclePermitNumber`, `insuranceCompany`, `insurancePolicy`), operador libre (`driverName`, `driverRfc?`, `driverLicenseNumber`), `distanceKm`, `departureAt`/`arrivalAt`, datos fiscales (`cfdiUuid`, `facturamaCfdiId`, `xmlUrl`, `pdfUrl` nullable hasta timbrar), cancelación (`cancelledAt`/`cancelledBy`/`cancellationReason`), `creatorId`.
  - `waybill_items`: snapshot por línea (`productId?`, `productCodeSnapshot`, `productNameSnapshot`, `satBienesTranspCode`, `satUnitCode`, `quantity`, `weightKg`, `isHazardousMaterial`, `hazardousMaterialCode?`).
  - `branches`: nuevas columnas nullable `addressStreet`, `addressExteriorNumber`, `addressInteriorNumber?`, `addressNeighborhood`, `addressMunicipality`, `addressState`, `addressCountry` (default `'MEX'`), `addressZipCode` — no rompe sucursales existentes.
- **Creación = timbrado en un solo paso** (sin draft, como `Sale`): `POST /api/v1/admin/waybills` valida sucursales + domicilios + stock suficiente en origen (rechaza negativo, a diferencia del POS) → aloca folio `TS` → mueve inventario atómicamente → arma payload SAT `CfdiType='T'` (Receiver = RFC propio, `CfdiUse='S01'`, sin impuestos, `Total=0`) → timbra vía Facturama → persiste snapshot completo.
- **Cancelación**: `POST /api/v1/admin/waybills/:id/cancel` revierte inventario (destino puede quedar negativo, igual que `CancelSaleUseCase`), cancela el CFDI si estaba timbrado, no idempotente (409 en doble cancelación).
- **Descarga**: `GET /api/v1/admin/waybills/:id/download?format=pdf|xml` proxy a Facturama.
- **Listado/consulta**: `GET /api/v1/admin/waybills` paginado con branch scoping por origen O destino; `GET /api/v1/admin/waybills/:id`.
- **Gateway Facturama propio del módulo**: `WaybillFacturamaGateway` (no reutiliza el de `billing`, evita import cruzado — mismo patrón que `payments`/`returns` instanciando `PrismaSaleRepository` localmente). `FacturamaRestGateway` real + `FakeFacturamaGateway` mock seleccionados por `FACTURAMA_MOCK`.
- **RBAC**: permisos `waybills:read`, `waybills:write`, `waybills:cancel`.

## Capabilities

### New Capabilities
- `waybills-api`: creación (con timbrado atómico), cancelación, descarga y consulta de traspasos de mercancía entre sucursales con Complemento Carta Porte (CFDI Traslado nacional); módulo hexagonal completo (dominio, use cases, repositorio Prisma, gateway Facturama propio, controller, DI).

### Modified Capabilities
- `inventory-api`: se resuelve el TODO de `branch_transfers` documentado en el requirement de stock negativo — se añade el requirement de que el movimiento entre sucursales vía traspaso Carta Porte rechaza negativo en origen (a diferencia de la venta).
- `admin-branches`: se agregan campos de domicilio fiscal estructurado (nullable, no breaking).

## Impact

- Nueva migración: `add_waybills_tables_and_branch_address` (tablas `waybills`, `waybill_items`; columnas nuevas en `branches`).

- Modificado: `openspec/specs/inventory-api/spec.md` (resuelve referencia a `branch_transfers` reservado), `openspec/specs/admin-branches/spec.md` (campos de domicilio).
- **Sin breaking changes**. Sin cambios de UI (alcance backend — ver change `carta-porte-ui` para frontend).
